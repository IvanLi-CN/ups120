# UPS 电源板硬件概览

## 总览

- 电源板通过多条控制与监测线缆连接至 ESP32 主控，承担 UPS 外部输入调节、放电路径控制与状态监测职责。
- 板上核心器件包括电源转换、热管理、输入保护以及电流电压测量等子系统。

## 关键器件清单

| 器件 | 主要作用 | 关键接口 / 配置 |
| --- | --- | --- |
| SC8815 | UPS 放电升/降压，稳定输出电压 | `CE`、`PSTOP`、`ADIN` |
| TCA6408A | 通过 I²C 扩展数字 IO，驱动/侦测 UPS 状态 | `P0`–`P7`、`RESET#`、I²C 地址 `0x20` |
| TPS2490 | 受控热插拔控制器，管理外部输入使能 | `EN`、`PG` |
| INA226 | I²C 功率监测，测量 UPS 外部输入功率 | `SDA`、`SCL`、`Alert` |
| FNTC0402X103F3380FB | 与 SC8815 形成热感测电路的 NTC 热敏电阻 | `ADIN` |
| 43 kΩ 上拉电阻 | 为 SC8815 `ADIN` 提供 3.3 V 基准 | `ADIN`、`3V3` |

## 互连关系

- **SC8815**
  - `ADIN` 同时连接 FNTC0402X103F3380FB NTC 和 43 kΩ 上拉电阻，组成温度分压网络。
  - `CE`（芯片使能）与 `P1`（TCA6408A 口线）相连，ESP32 可经 I²C 控制启停转换。
  - `PSTOP` 与 `P2`（TCA6408A）连接，用于控制放电停止逻辑。

- **TCA6408A I/O 扩展器**
  - 经 I²C 总线 (`SCL`/`SDA`) 连至 ESP32 主控。
  - I²C 地址配置为 `0x20`（A0–A2 接地）。
  - `P0` 读取/驱动 `IN_PG` 网络，实现输入电源良好状态反馈。
  - `P1` 输出控制 SC8815 `CE`。
  - `P2` 输出控制 SC8815 `PSTOP`。
  - `P3` 连接智能电池 `ALERT`（透传到 BQ76920），用于异常报警。
  - `P4`–`P7` 当前悬空未使用。
  - `RESET#` 由 ESP32 直接驱动，确保 I/O 扩展器复位同步。

- **TPS2490 热插拔控制器**
  - `EN` 接 `IN_EN` 网络；低电平时切断 UPS 外部输入。
  - `PG` 为开漏 Power Good 指示脚，由 TPS2490 根据外部功率 MOSFET 的 `VDS` / 启动状态机 / 保护状态综合判定；导通良好时释放为高（上拉后读到高电平），启动中、UVLO、限流或保护时拉低。
  - `PG` 直接并入 `IN_PG` 网络，送至 TCA6408A `P0` 与 ESP32，仅表达“输入功率路径是否被判定为良好”，并不等同于“适配器电压存在”。

- **INA226 功率监测**
  - 与 ESP32 共享 I²C 总线，实时报告 UPS 外部输入电压、电流与功率。
  - `Alert`（若使用）可与 TCA6408A 或 ESP32 中断输入共享，辅助告警逻辑。

- **ESP32 主控**
  - 通过 I²C 控制 TCA6408A 与 INA226，间接管理 SC8815 放电和输入监测。
  - 直接线控 TCA6408A `RESET#` 以及 `IN_EN` 网络（若由 ESP32 驱动 TPS2490 EN）。

## 信号网络简述

- `IN_EN`：由 ESP32 控制，使 TPS2490 允许或切断外部输入。
- `IN_PG`：TPS2490 `PG` 开漏指示，馈入 TCA6408A `P0` 与 ESP32，表示“功率 MOSFET 路径良好/未处于保护”，不直接代表外部母线电压是否超过某阈值。
- `ALERT`：智能电池（BQ76920）故障或保护触发时输出高电平，通过 TCA6408A `P3` 传回 ESP32。
- `ADIN`：SC8815 热补偿输入，结合 NTC 与 43 kΩ 上拉监控温度。

## AC GOOD 信号路径概览

- **PG 原始层**：TPS2490 `PG`（开漏，良好时被上拉为高）→ `IN_PG` 网络 → TCA6408A `P0` → `in_pg_raw`（固件中读取的布尔，保留原始电平含义）。
- **电压在线层**：INA226 通过同一 I²C 总线测量输入母线电压，固件字段 `vin_meas_mv`；布尔 `vin_online`（推荐命名）= `vin_meas_mv > UPS_VBUS_AC_ONLINE_MV = 11.5 V`。
- **综合 AC GOOD 层**：`power::power_task` 将 `PG` 语义化布尔（建议名 `pg_asserted`）与 `vin_online` 组合得到 `ac_present`，并施加 10 s 稳定窗口得到 `ac_stable`。UI、充电/放电策略均消费 `ac_present` / `ac_stable`，不直接使用 `IN_PG`。
